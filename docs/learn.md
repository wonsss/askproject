# 도메인 맵·용어 사전 학습

`config/domains.yaml`(기획자 관점 도메인과 허용 경로)과 `config/glossary.yaml`(한국어 기획 용어 → 코드 식별자)을
사람이 YAML로 쓰지 않아도 되게, AI가 초안을 쓰고 사람이 항목별로 승인한다. 빈 템플릿이면 스코핑이 늘 전체 범위로 돌아
느리고 비싸다. 반대로 `paths`가 틀리면 그 도메인 질문에서 해당 코드를 아예 못 본다(하드 필터). 그래서 **덮어쓰지 않는다**:
초안 → 결정적 검증 → 미리 보기 → 항목별 승인 → 적용.

## 흐름

| 단계 | 명령 | API 비용 |
| --- | --- | --- |
| 예상 비용·재료 확인 | `askproject learn domains --dry-run [--json]` | 없음 |
| 초안 + 검증 | `askproject learn domains [--json]` (터미널은 예상 금액을 보여 주고 확인을 받는다, `--yes`로 생략) | 있음 ([cost.md](cost.md)) |
| 적용 | `askproject learn domains --apply <제안 id> [--accept a,b]` 또는 `--apply -` + 표준 입력 `{"proposal_id": "…", "accept": ["a"]}` | 없음 |

`glossary`도 같다. 앱은 설정 → 도메인·용어에서 같은 명령을 부른다(학습하기 → 확인 창의 예상 금액 → 진행 → 미리 보기 체크 → 적용).
적용하면 실행 중인 봇을 다시 시작해 새 도메인 맵을 읽게 한다.

## 초안 (에이전트)

- 재료(결정적, 프롬프트에 넣음): 인덱스의 폴더 구조와 파일 수, 구조 맵의 화면(라우트·앱 manifest)·API, 레포 문서·노션·슬랙
  수집본 제목, 감사 로그의 최근 질문 40개(가린 질문·eval 제외), 범위를 잘못 잡은 사례(아래), 지금 파일 내용.
  동기화(`askproject sync`)가 먼저 돼 있어야 한다.
- 에이전트는 기존 `AgentRunner` 포트로 돌고, 읽기 전용 도구(`list_dir`·`code_search`·`read_code`·`find_screen`·`find_api`·
  `search_docs`·`read_doc`)만 쓴다. 학습용 도구 호출은 감사 로그(`tool_calls`)에 남기지 않는다.
- 모델 `model_large`(기본 claude-sonnet-5-5), 상한 domains 20회·glossary 16회 대화, 비용 상한 $2.0(api 모드).
  대화 수 상한은 실측에서 지켜지지 않았다(SDK가 세는 방식이 다름, 42회까지 감) — 실제 안전장치는 금액 상한이다. 1회 실측 $0.77~1.29([cost.md](cost.md)).

## 검증 (LLM 아님)

| 대상 | 규칙 |
| --- | --- |
| 도메인 id | 영문 소문자·숫자·`-`·`_`, 아니면 버림 |
| `paths` 패턴 | 인덱스 파일에 하나도 안 걸리면 그 패턴을 버림(경고). `**`처럼 레포 전체를 여는 패턴·레포 밖 경로도 버림. 남은 패턴이 없으면 도메인을 버림 |
| 넓은 도메인 | 레포 파일의 50% 넘게 걸리면 경고 |
| 용어 식별자 | `rg --fixed-strings --case-sensitive`로 레포에 있는지 확인(제외 규칙 적용). 없으면 버리고, 남은 게 없으면 용어를 버림. rg가 없으면 경고만 |
| 미분류 비율 | 어느 도메인(·shared)에도 안 걸리는 파일 비율 — 지금 / 모두 적용 시, 많이 남는 폴더 5개 |
| 범위 사례 | 아래 사례가 풀리는지 — 지금 / 모두 적용 시(잠긴 항목은 바뀌지 않는 것으로 셈), 남는 사례 최대 8개 (도메인만) |
| 차이 | 항목마다 추가·변경·삭제·잠김·같음. 삭제는 학습이 썼던 항목이 이번 초안에 없을 때만 제안하고 기본 선택하지 않는다 |

## 적용과 잠금

- 승인한 항목만 병합한다. 파일 맨 앞 주석(머리말)은 그대로 두고, `shared` 등 다른 키도 유지한다. 도메인에는 근거(`evidence`)를 함께 쓴다.
- 쓰기 직전 기존 파일을 `backups/config/<이름>-<시각>.yaml`(앱 모드는 ~/Library/Application Support/AskProject/backups/config)에 복사하고,
  `paths.atomic_write`로 쓴다. 쓰기 전에 스코핑 로더가 읽을 수 있는지 확인한다.
- **제안을 만든 뒤 파일이 바뀌었으면 적용하지 않는다**(제안에 파일 해시를 남겨 비교). 미리 보기 사이에 손으로 고친 내용을 덮지 않는다.
- 학습이 쓴 항목은 지문을 `data/learn/learned.json`에 남긴다. 지문이 없거나(사람이 쓴 항목) 다르면(사람이 고친 항목) **잠김** —
  다음 학습은 그 항목을 바꾸지 않고 제안으로만 보여 주며, 초안에 없어도 삭제를 제안하지 않는다.
  도메인은 `locked: true`로 명시적으로 잠그고, `locked: false`로 풀 수 있다(용어 사전은 값이 목록이라 지문만 쓴다).
- 제안은 `data/learn/proposals/`에 최근 20개만 둔다.
- 아직 적용·버리지 않은 마지막 제안은 `--dry-run` 응답의 `pending`으로 돌려준다(마지막 적용보다 뒤에 만들었고 파일이 그대로일 때만,
  학습 뒤 커밋이 바뀌었으면 `stale` 안내). 앱은 화면을 열 때 이것을 미리 보기로 다시 띄운다 — 창을 닫거나 앱을 다시 켜도 학습 비용을 다시 들이지 않는다.
  '버리기'는 `learn <kind> --dismiss <id>`로 표시해 다시 뜨지 않게 하고, 적용하면 제안에 `applied_at`이 남는다.
- 스코핑 로더(`pipeline/scoping.parse_domain_map`)는 `evidence`·`locked` 같은 필드를 무시하고, 비었거나 `null`인 목록을 견딘다.

## 다시 학습

레포 구조가 바뀌어도 자동으로 다시 학습하지 않는다(비용). 마지막 적용 때의 2단계 폴더 목록과 지금 인덱스를 비교해,
새 폴더가 생겼으면 `--dry-run` 결과의 `relearn_hint`(앱에서는 파란 안내)로 알려 준다.

## 피드백·범위 사례 반영

감사 로그에서 스코핑이 범위를 잘못 잡은 사례를 결정적으로 골라(`learn.scope_cases`, LLM 아님) 재료에 넣고 검증에도 쓴다.
최근 질문 2000개를 훑어 종류별로 최근 30개(같은 질문은 한 번), eval·가린 질문은 뺀다. 학습을 따로 돌리지는 않는다 —
다음에 학습할 때 반영된다(자동 재학습 없음). 사례 수는 `--dry-run`의 `materials.cases`와 앱 재료 줄에 보인다.

| 사례 | 감사 로그 근거 | 재료에서 에이전트에게 바라는 것 | '풀림' 판정 |
| --- | --- | --- | --- |
| 범위 넓힘 | `tool_calls`의 `widen_scope` + 그 질문에서 읽은 파일(`read_code`)·검증된 코드 인용 중 잡은 도메인 paths·shared 밖 파일 | 그 파일을 맞는 도메인 paths에 넣기 | 범위 밖 파일이 모두 잡은 도메인 paths(·shared)에 걸림 |
| 되묻기 선택 | 사용자가 되묻기 버튼으로 고른 범위(`scope.forced`, `사용자가 범위 선택`) | 질문의 기획자 낱말을 고른 도메인 terms에 더하기 | 고른 도메인 terms의 단어가 질문에 들어 있음(스코핑의 `term_matches`와 같은 규칙) |
| 👎·확인 요청 | `feedback`의 `down`·`escalate` | 참고만(원인이 범위가 아닐 수 있음) | 판정 없음, 수만 셈 |

용어 사전 학습도 같은 사례를 재료로 받아, 그 질문에 나온 기획 용어를 우선 다룬다(판정은 하지 않는다).
'풀림'은 스코핑이 다음에 그 도메인을 고를 가능성이 생겼다는 뜻일 뿐, 답이 좋아졌다는 보장은 아니다 — 아래 eval로 확인한다.

## 품질 확인: 학습 전후 eval 비교

학습이 실제로 답을 좋게 했는지는 골든 세트로 본다. **eval은 API 비용이 든다(api 모드 전체 1회 약 $0.85, 문항 수에 비례) — 실행 전에 금액을 확인한다.**

1. 학습 전: `uv run askproject eval` → `eval/results/`에 결과(정답률·범위 재현율·비용·응답 시간)
2. 학습·적용: `uv run askproject learn domains` → 미리 보기 확인 → `--apply`, 필요하면 `learn glossary`도
3. 학습 후: 같은 문항으로 `uv run askproject eval` (일부만 보려면 `--ids q01,q02` — 두 번 모두 같은 문항으로)
4. 비교할 것: 범위 재현율(정답 도메인이 범위에 들었나 — 떨어지면 `paths`가 좁다), 정답률, 질문당 비용·시간(범위가 좁아지면 줄어야 한다),
   결과의 `tool_calls`에 있는 `widen_scope` 수(범위 미스). 나빠지면 백업(`backups/config/`)으로 되돌린다.
